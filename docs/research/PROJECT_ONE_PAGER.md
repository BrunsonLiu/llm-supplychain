# 项目一页纸（简历/面试用）

项目名：**Conformal 风险控制下的两阶段履约决策**
版本：v5.9.0　代码：本仓库　数据：Online Retail II（1,014,625 行清洗后，4,707 SKU，104 周）

---

## 1. 一句话定位

> 把「保证服务水平」写成**可校验的 CVaR 约束**，用 conformal 校准 cap，并测出它的真实成本门槛：**溢价 > 0 当且仅当持有成本 > 缺货成本**，跨 9 个网络变体验证。

不是「用了什么新模型」，而是「把一个模糊承诺变成可检验的命题，并给出答案」。

---

## 2. 简历条目（可直接用）

**供应链履约优化 / 不确定决策（个人项目，v5.9）**

- 在真实电商交易数据（101 万行 / 4,707 SKU / 104 周）上构建两阶段随机履约模型：第一阶段布点 + 库存总量，第二阶段分配 + 缺货，CP-SAT 求解，含 handling / holding / shortage / CVaR。
- 用 split-conformal 在 held-out 场景上校准 `CVaR_alpha(unmet)` 上限：90% 目标经验覆盖 **88.0%**；在线 ACI 版本长期覆盖 **92.3%**，平均区间宽度降低 **38%**（11,022.7 → 6,813.4）。
- 用二分法量化三种杠杆的可达下界：固定库存 floor **1,485 > cap 1,431（不可行）**；加库存降到 **23.2**；加产能 2× 和提速 1400 km/day **均无效果**——证明瓶颈是布点而非吞吐或时效。
- 30-seed 重复实验测稳健性溢价，发现单次抽样会高估 2–3 倍（h=2：105.5 → 37.3）；跨 9 个网络变体证明溢价开关由 `holding vs shortage` 决定，**onset 恰好等于 shortage_cost**（1.0/2.0/4.0）。
- 工程：385 个测试、可复现 benchmark（`--quick --lever-seeds 30 --cross-instances 10`）、OR-Tools GLOP/SCIP + 可选 Gurobi 对偶对比、DuckDB SQL 数据层。

> 说明：最后一条是工程附录，不是研究主线；面试时一句话带过即可。

## 3. 三个能讲 30 分钟的技术点

### 点 1：cap 不是拍的，是校准出来的

```text
cap = conformal 上分位( {unmet_i} , ceil((n+1)(1-δ))/n )
```

- 用 held-out 场景，不用训练场景；
- 报的是经验覆盖，不是「约等于 90%」；
- 已知缺陷：这是**场景级**校准，不是策略级有限样本保证。

追问预案：「这算 Conformal-DRO 吗？」→ **不算**，是场景级 split-conformal；真正的 DRO 集没实现，这是明确的 future work。

### 点 2：不可行本身是结果

固定库存时 floor 1,485 > cap 1,431。第一反应是调求解器，正确反应是问：**物理上能不能做到？**

用二分法把「能做到多少」问出来：

| 杠杆 | floor |
|---|---:|
| 无 | 1,485 |
| 库存 | 23.2 |
| 产能 2× | 1,485 |
| 提速 | 1,485 |

结论：这个网络不是吞吐受限，也不是时效受限。

### 点 3：门槛是成本比，不是网络结构

```text
溢价 > 0  ⟺  holding_cost > shortage_cost
```

机理一行：多备一单位花 holding，少缺一单位省 shortage。所以 `h < s` 时无约束最优解本来就满足 cap，溢价恒为 0。

9 网络 × 10 seed 验证：onset 全部等于 shortage_cost。

**这条最能体现研究品味**：把一个「算法问题」还原成一个「单位经济学问题」。

## 4. 面试追问预案

| 追问 | 要点 |
|---|---|
| 覆盖 88% 为什么不是 90%？ | 有限样本 + horizon 13 + 单目标周；ACI 用来补长期覆盖 |
| CVaR 怎么算的？ | 场景等权 + `eta + 1/(1-α)Σw·excess`，整数化到分 |
| 为什么用 CP-SAT 不用 Gurobi？ | 无 license 依赖；另有 transport LP 用 GLOP/Gurobi 验证对偶一致 |
| 场景怎么来的？ | bootstrap / Gaussian copula / conformal 区间三选一，权重等权 |
| 6 个场景够吗？ | 不够；CVaR 近似 worst-case，所以做 30-seed 重复 |
| 为什么溢价会跳？ | 铺满所有场景需 ~2.4× 需求库存（DC 级布点要同时覆盖不同场景） |
| 结论能推广吗？ | 只能说在这个建模选择下成立：库存可调 + 缺货按单位计罚 |
| 你和别人做的有什么不同？ | 别人报覆盖率和宽度；我报「保证要花多少钱、什么时候开始花钱」 |
| 最诚实的负面结果？ | 产能和时效完全无效；LinUCB 打不过 UCB1 |
| 如果重做一次？ | 先做多实例 + 多种子，再做单实例深挖；单次实验会骗人 |

---

## 5. 主动说的四条限制

1. 场景级校准，不是策略级保证；
2. 单数据集、单实例、6 场景小样本；
3. 门槛结论依赖「库存可调 + 单位罚金」；
4. 单次实验溢价高估 2–3 倍——这类结论必须重复抽样。
